## Important current limits

- Candidate application stage remains masked as `received`; Inbox now supports own screening notices only. No submission/appointment/Pass/Offer/Hired notices, full progress timeline, owner-finalization alerts, hide UI or backfill. Screening notices have no expiry; old interview-retention command unchanged.
- `review_ready` is accepted vocabulary but has no workflow writer. Processing and review state are separate from recruitment stage.
- Publication freezes the current plan, including empty; explicit zero-interview owner Offer is enabled. Existing published data is not reconfigured/reset. Full notification/owner-availability effects remain separate work.
- CSV screening/readiness/release with UI/list/filter is source-implemented but not deployed/DB-integrated. No reversal, panels, interview retries or reopening. Closing a vacancy still stops intake, not ongoing interviews. Operational/uncertain/unclassified failures require explicit release, not inferred readiness after retry exhaustion. SQL/detail readiness parity, native release UX and authenticated isolation remain real integration/manual QA, not established by mocks/DOM tests.
- Draft vacancy/interview-plan and review no-op handling is source-implemented, not a general revision/history framework or real DB/HTTP verification claim. Candidate-form and screening-import navigation guards remain R3d-c. Counters remain concurrency controls, not history.
- Live failures returned by the executor persist non-retryable, but interrupted execution recovery marks processing tasks retryable without knowing whether a paid attempt occurred. [Safety detail](jev-safety.md#recovery-limitation).
- PDF only for real parsing (DOCX may be accepted as an upload, but cannot be parsed). No OCR, guaranteed complex-layout reading order, rectangles or extraction-quality measurements.
- Private storage can retain orphans after crashes/cleanup failures. No global storage quota/reconciliation yet.
