## Verification strategy

Default for later approved verification checkpoints: rebuild affected packages, typecheck and run meaningful ordinary tests; targeted `vacancies:check`, `applications:check`, `processing:check`, `extraction:check` or `interviews:check` only for affected contracts. They start local test applications and mutate/clean tagged PostgreSQL/file fixtures. Explicitly select disabled live executor/fixture ports, never rely on ambient live configuration. Ordinary fixtures are not Jev spending-limit tests.

Current exception at the user's request: R2 and R3a may be merged without application test execution; retain Q-R2A/Q-R2U/Q-R3A as visible outstanding work. Static compilation/diff/docs checks are not behavioral regression evidence. User UX checks can wait for a future batch; do not replace them with headless/browser automation or provider experiments. Avoid repeated broad runs during churn and record only checks actually executed; no invented pass counts. Future testing batches require their bounded scope, not waiting silently for the whole redesign to finish.
