## Verification strategy

Default for later approved verification checkpoints: rebuild affected packages, typecheck and run meaningful ordinary tests; targeted `vacancies:check`, `applications:check`, `processing:check`, `extraction:check` or `interviews:check` only for affected contracts. They start local test applications and mutate/clean tagged PostgreSQL/file fixtures. Explicitly select disabled live executor/fixture ports, never rely on ambient live configuration. Ordinary fixtures are not Jev spending-limit tests.

Current exception at the user's request: R1/R2/R3a/b may be merged without application test execution; retain their Q-* automated/manual follow-ups as visible outstanding work. Drafted tests/updated fixtures are not executed passes. Static compilation/diff/docs checks are not behavioral regression evidence. User UX checks can wait for a future batch; do not replace them with headless/browser automation or provider experiments. Avoid repeated broad runs during churn and record only checks actually executed; no invented pass counts. Future testing batches require their bounded scope, not waiting silently for the whole redesign to finish.
