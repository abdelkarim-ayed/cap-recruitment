### Gaps the first integration plan must resolve

- **Envelope/identity:** one logical CV extractor per file input versus old task rows; field/question/output IDs, ordering and repeated types. Lab IDs accept capitals and coverage lists up to 254; main key/task/correction/body/request bounds differ. Specify mapping/validation, not silent limit increases or lower-casing collisions.
- **Dates/migrations/compatibility:** publication date timezone and authoritative stored field, immutable snapshot propagation; what happens to already-published vacancies lacking a trustworthy first-publication date, old `extractSkills` results/corrections and demo/reset fixtures. Do not backdate from `updated_at`, silently rerun successful work or rewrite frozen history. Development data is disposable but major ER changes/data execution still need scope/approval.
- **Results/review/export:** exact Choice/category/count validation, probability completeness and rounding tolerance, raw response/model/usage storage, null/failure states, field-level corrections/no-ops and CSV headers/source/unknown encoding. No calibrated thresholds/caps or competence interpretation selected. Expected education has no separate awarded flag; display its window.
- **Caches/attempts:** parser-version/options identity vs hydrated-request-byte identity; private storage/bounds/retention/ownership, fixture/live separation, equality/integrity checks, duplicate-send exclusion across workers, attempt-before-send and unknown-completion handling. A cache hit cannot bypass authorization or reopen released/completed/screened work. Successful historical response use must not double-count spending usage.
- **Runner:** bounded enqueue/claim/wake/stop/non-overlap/shutdown/guard-block behavior and parser cancellation. Existing HTTP submission must remain bounded and not execute native parsing/provider work inline. Do not assume a lab CLI or the gateway's local/RxJS serialization supplies scheduling/exactly-once behavior.
- **Parser feasibility and quality policy:** offline Node parity on representative already-parsed PDF fixtures, warnings/empty/garbled/unsupported input handling; explicit skill negation/international mappings remain open. Retain substantive uncertain answers for HR without inventing thresholds, missing categories, automatic caps or extra questions.
